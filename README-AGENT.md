## Запуск

```sh
python3 -m http.server 8765 --bind 127.0.0.1 --directory dist
```

Актуальная игра: <http://127.0.0.1:8765/>. Сначала проверить порт и путь процесса;
не завершать неизвестные серверы. Оставлять сервер доступным после работы.
Сохранения зависят от origin: `127.0.0.1` и `localhost` имеют разные localStorage.
Браузерные проверки выполнять в отдельном профиле, не менять сохранение пользователя.
На этой машине Node: `/opt/homebrew/bin/node`. Сборка и npm для игры не нужны.

## Код и данные

[README.md](README.md) описывает игру; [docs/runtime.md](docs/runtime.md) — модули,
порядок загрузки и цикл кадра. `dist/` — исходники и одновременно готовая игра.
Прикладные файлы подключены с `data-app`; проверки читают их из `index.html`.
Однофайловый экспорт: `python3 data-tools/build-standalone.py /absolute/path/game.html`.

- `physics.js` — физические модели и планировщик, `simulation.js` — время и
  исполнение этапов, `navigation.js` — маршруты. Не менять физическую точность
  ради ускорения представления.
- Физика использует только 3D-координаты `p3`. Раскладка, обычная карта, срез и
  радиальная схема — представление. Не пересчитывать каталоги ради правки UI.
- Физические единицы Rocket — тонны, Stellar/Magnetic — килограммы. Актуальные
  параметры задаёт `ShipPhysics`; ранние записи истории про миллиграммы устарели.
- Не удалять `lastSample` у wind/magnetic: повторное интегрирование по кадрам
  раньше приводило к дрейфу и пропущенному прибытию. Кэш границы `MissionReach`
  переиспользует сертифицированный план свободного полёта с проверками инвалидации.
- `flight-view.js` связывает корабль и отметки с концами маршрута. Орбитальные
  смещения отображения учитываются отдельно от неизменного физического плана.
- Сохранение `parus-expedition-v1`, формат 13. Сохранять совместимость старых
  версий, топливо, позицию и часы. Восстановление каталожных ссылок предшествует
  восстановлению маршрута. Закреплённые цели нельзя заменять кэшем тайлов.
- Незвёздная конечная цель открывает игровую звезду **при прибытии** в той же
  точке. Предпросмотр не регистрирует её на карте, в поиске или сохранении.
  Старые активные планы и орбитальные стоянки сохраняют физику.
- Каталоги и источники описаны в [docs/catalog.md](docs/catalog.md), обработка —
  в [data-tools/README.md](data-tools/README.md). Активные снимки задают
  `current.json`; не переписывать их при работе только над представлением.
  Не выдавать неизвестные или типичные параметры за измеренные значения.
- Не коммитить `.env`, ключи, сырые дампы или экспортные архивы. Атрибуцию данных
  и шрифтов сохранять в `THIRD_PARTY_NOTICES.md`.

## Проверка изменений

```sh
node verify.mjs
node verify-stream.mjs
```

Выбирать дополнительные проверки по изменённому слою; отдельная регрессия
оптимизаций — `node verify-runtime-performance.mjs`. Проверять синтаксис и
`git diff --check`. Для изменений карты/интерфейса дополнительно проверять
браузером обе темы, desktop/mobile, full/slice/radial, поиск и настоящий полёт
с сохранением/reload. Сервер должен отдавать именно проверенные файлы.

Полная история прежних задач, ограничений и проверок сохранена без удаления в
[docs/agent-history.md](docs/agent-history.md). Это хронология, а не набор
актуальных инструкций: поздние записи заменяют ранние требования. Текущие
формулы и допущения — в [docs/physics.md](docs/physics.md), карта — в
[docs/map-visualization.md](docs/map-visualization.md).
