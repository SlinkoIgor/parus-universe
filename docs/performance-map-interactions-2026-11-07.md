# Зависания при зуме и смене проекции · 06–07.11.2026

## Причина

Холодный поиск космологической привязки проходил по `GALAXIES` и для каждой
галактики снова вызывал `OBJECTS.find`. Реестр `GALAXIES` сохраняет метаданные
ранее просмотренных тайлов. После обзора нескольких тысяч галактик стоимость
первого прохода увеличивалась; `MapSlice.setMode` очищает кэш привязок.
Любое ненулевое `cosmicTime` включает этот путь, поэтому свежая игра при t=0
плохо воспроизводила проблему продолжающейся экспедиции.

Дополнительно `mapContext` строил полигоны всех подходящих галактик до проверки
двух очевидных солнечных контекстов. У выгруженной галактики он проецировал
вспомогательную запись без полного `kind`, что вновь включало поиск привязки
среди галактик. Этот синхронный код вызывается непосредственно из wheel,
перетаскивания и переключателя проекций.

В отдельном Chrome после накопления 3263 галактик и установки ненулевого
космического времени переключение не завершилось за минуту: renderer занимал
почти 100% одного ядра. Изолированный профиль пришлось закрыть; сохранён нативный
sample. После исправления заголовка первый кадр ещё занимал **17182,8 мс** при
2685 записях галактик. После замены повторных поисков индексом аналогичный
первый проход занял **623,3 мс**. Это отдельные воспроизведения, не статистика
всех устройств или одинаковый зафиксированный набор каждого принятого тайла.

CPU-профили обычного зума показали ещё одну большую статью расходов:
тесселяция заведомо невидимых областей и галактических контуров меньше двух
пикселей. Проверка экрана раньше выполнялась после построения полигонов.

Наконец, четыре старых запроса предыдущего вида могли продолжать занимать
общую очередь после переключения проекции. В исходном браузерном прогоне
радиальный вид оставался без потокового слоя с четырьмя занятыми слотами.
Сама медленная загрузка не блокирует JavaScript, но задерживает появление карты.

## Исправления

- Поиск привязки сохраняет прежний порядок галактик, первые записи каждого ID
  и прежний приоритет OBJECTS/ExtendedCatalog. Во время рисования используется
  существующий индекс кадра; вне кадра строится свежий локальный индекс.
  Формулы, условия принадлежности и численная точность не меняются.
- Заголовок сразу возвращает солнечные контексты; проверяет только доступные
  полные записи галактик, начиная с наименьших. Метаданные выгруженных тайлов
  не передаются в геометрический и космологический поиск заголовка.
- Точные аналитические границы полного объекта консервативно отбрасывают
  невидимые контуры до тесселяции. Срез и частично видимые/окружающие экран
  области сохраняются. Проверка принадлежности точки также сначала использует
  границы, затем прежний полигон. Для оставшихся контуров точность прежняя.
- Запросы ненужных тайлов отменяются при смене покрытия и проекции. Слоты
  освобождаются сразу. Запоздалый результат не принимается и не удаляет новый
  запрос того же файла; отмена не включает задержку повторной загрузки.
  Запрос, которым воспользовались поиск, связанные системы или навигация,
  защищён от отмены карты. Встроенные каталоги однофайлового экспорта тоже
  проверяют отмену перед декодированием.

Общий реестр галактик намеренно сохраняет прежнее содержимое: он используется
также физической моделью принадлежности. Оптимизация не удаляет из него записи
и не меняет физику ради ограничения списка контуров. Данные и формат сохранения
не пересобирались. Обновлены ключи кэша изменённых скриптов.

## Попарные замеры зума

Chrome 157, 1440 × 1000, DPR 1, отдельный профиль. Три чередующиеся пары по
40 кадров с настоящим RAF, масштаб увеличивается в каждом кадре. Набор объектов
внутри пары фиксирован, кэш геометрии очищается между сериями. Сравнение включает
и отключает только предварительную проверку границ; это не замер всех
исправлений вместе. Таблица — медиана средних времён JavaScript кадра.

| Вид | Без раннего отсечения, мс | С отсечением, мс | Сокращение |
| --- | ---: | ---: | ---: |
| Ближайшие звёзды | 28,88 | 13,99 | 51,6% |
| Млечный Путь | 54,77 | 40,98 | 25,2% |
| Галактики, ширина 100 млн св. лет | 115,69 | 23,75 | 79,5% |

У двух последних сцен часть точечных тайлов оставалась в загрузке. Сравнение
использовало одинаковый принятый набор; полные структурные слои были готовы.
Эти числа не являются гарантией 60 FPS. Тяжёлый галактический вид и первый
проход после смены проекции ещё могут давать заметную задержку.

## Проверки

`verify-map-interaction-performance.mjs` включена в общий набор и проверяет
2000 выгруженных записей при ненулевом времени, смену проекций, отсутствие
вложенного сканирования каталога, приоритет дубликатов, прямые замены записей,
границы/срез/попадание, отмену и запоздалые ответы, повтор того же файла,
защиту поиска/навигации и неизменность экспедиции.

Прошли отдельные verify-map, verify-stream, verify-runtime-performance,
verify-map-render-cache, verify-orbit-paths, verify-galaxy-identities,
verify-system-view и новая регрессия. Браузер:

- 48 попарных сравнений: dark/light × desktop/mobile × full/slice/radial ×
  звёзды/Галактика/галактики/Вселенная. PNG canvas, попадания по точкам,
  контуры областей/галактик, подписи и физическое состояние совпали точно.
- Настоящие поиск Сириуса A, запуск, пауза, wheel и перетаскивание,
  переключатели full/radial в обеих темах на desktop/mobile, точный save/reload
  плана/топлива/часов и прибытие с предсказанным топливом. Исключений JS нет.
- Скриншоты просмотрены. Проверки выполнялись в отдельном Chrome-профиле;
  пользовательские сохранения не менялись.

Отдельный verify-cosmology проходит физические утверждения, затем падает на
прежнем ожидании `focusShip()` → `followShip === false`: текущая кнопка первым
нажатием включает слежение. Подстановка исходных файлов до этой задачи в
отдельном процессе даёт тот же сбой. Чужой тест и поведение кнопки не менялись.
verify-map-radial остановлен после нескольких минут на синхронном чтении
прежнего `map-radial/bae60fefac05/point-253.json`; sample/lsof сохранены.
Полный `verify.mjs` выполнил 24 PASS, включая составные/космологические полёты,
и не завершился за установленный лимит 90 секунд. Это неполный, не успешный
прогон. `verify-stream.mjs` завершился с exit 0 за 4,1 секунды. Синтаксис
изменённых JS/test-файлов и scoped diff-check прошли; HTTP index и все 58
подключённых JS/CSS совпадают с диском, восемь ключей кэша соответствуют SHA-256.

## Дальнейшие возможности

1. Пространственный индекс сфер принадлежности галактикам с сохранением
   прежнего порядка выбора и строгой инвалидацией может уменьшить оставшийся
   холодный поиск. Сейчас устранено повторное сканирование всего OBJECTS,
   но сами подходящие галактики по-прежнему проверяются по очереди.
2. Построение сложной геометрии и декодирование крупных тайлов можно перенести
   в worker с версионированием ответов по виду. Это уменьшит блокировку главного
   потока; потребует отдельной проверки подписей, выбора и экспорта.
3. Обновления подписи/DOM от частых wheel/pointermove можно объединять до одного
   обновления на кадр. Преобразование камеры и накопленное движение должны
   сохраняться, как и точный результат после завершения жеста.
