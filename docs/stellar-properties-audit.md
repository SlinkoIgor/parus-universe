# Отсутствующие физические параметры звёзд · 29.10.2026

Проверена цепочка Lacaille 9352 = GJ 887 = HIP 114046 = hyg-113687: исходный HYG v4.1 → build-full-catalog.py → компактные записи → ExtendedCatalog.decode/init → MapDetails.massInfo → физика разгона/прибытия.

В схеме всех 119 626 исходных строк HYG **нет поля массы**. Поэтому массовые HYG-звёзды без отдельного литературного дополнения не потеряли массу при импорте: этот источник её не поставляет. Поле lum HYG — величина из визуальной абсолютной звёздной величины; его намеренно нельзя считать болометрической светимостью. Подмена этой величины дала бы систематическую ошибку разгона.

В загруженном основном слое на дату аудита 955 объектов star/home, из них 17 имеют непустую массу по MapDetails.massInfo (это покрытие основного слоя, не всего атласа; литературная оценка не обязательно прямое измерение). Локальное дополнение Lacaille сохраняется, но оно не решает нехватку физических параметров у остальных звёзд. При действительно неизвестной массе гравитация источника в расчёте пропускается с явным пояснением. Это допущение, не измеренный ноль.

Для системного обогащения подходит, например, опубликованная [таблица Mann et al. 2015 для 183 K/M-карликов](https://vizier.cfa.harvard.edu/viz-bin/VizieR?-source=J/ApJ/804/64), DOI [10.1088/0004-637X/804/1/64](https://doi.org/10.1088/0004-637X/804/1/64). Она различает эмпирические и модельные параметры; M0/e_M0 — модельно выведенная масса и её ошибка, не динамическое измерение. Значения нельзя произвольно смешивать с другими оценками из более поздних работ. Доступ к машинной выгрузке во время аудита не подтвердился, поэтому новая таблица не объявлена импортированной.

Следующий импорт физических свойств должен быть общим слоем сопоставления по устойчивым идентификаторам (Gl/GJ, HIP и др.), с проверкой компонента системы и координат. Он должен применяться одинаково к основному слою, декодированным тайлам и восстановленным pins; сохранять источник каждого поля, номинал, неопределённость и метод. Совпавшие индивидуальные значения использовать по объявленной политике приоритета; неоднозначные сопоставления и отсутствующие данные оставлять явно неизвестными. Проверять несколько звёзд, а также конфликты ID, двойные системы и перезагрузку сохранений. Не назначать массу по спектральному классу как будто это индивидуальное измерение.

Постоянное правило поиска общей причины и исправления всех затронутых записей записано в AGENTS.md.
