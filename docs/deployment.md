## Размещение

- Существующий DigitalOcean VPS: `root@165.232.99.124` (SSH по уже настроенному ключу).
- Nginx раздаёт статику; Umami использует отдельную базу `parus_umami` в PostgreSQL.
- `/srv/parus/current` — ссылка на активный релиз.
- `/srv/parus/releases/<release>/site` — публичные файлы.
- Рядом с `site` находятся `manifest.json` и `sha256sums.txt`; Nginx их не раздаёт.
- `/srv/parus/deployment/active.json` — активный релиз, время и исходный коммит.
- Конфигурация: `/etc/nginx/sites-available/parus`, ссылка в `sites-enabled`.
  Проверенная копия: [deployment/parus.nginx.conf](../deployment/parus.nginx.conf).
- Логи: `/var/log/nginx/parus.access.log` и `parus.error.log`.

HTTP перенаправляется на HTTPS. Certbot использует webroot
`/var/www/parus-acme`, отдельный сертификат
`/etc/letsencrypt/live/parus.165.232.99.124.sslip.io/` и системное автопродление.
Существующий общий deploy hook Certbot проверяет и перечитывает Nginx.
Сайты `point` и `default`, их процессы и данные при публикации не заменяются.

## Обновление

1. Создать неизменяемый локальный снимок текущих файлов и каталогов, записать
   SHA-256 каждого файла. Проверить его через `node verify.mjs` и браузером.
2. Передать снимок в новую папку `releases/<release>/site`, а манифест и список
   контрольных сумм — в родительскую папку релиза. Не менять файлы активного релиза.
3. В папке нового `site` выполнить `sha256sum --quiet -c ../sha256sums.txt`.
4. Атомарно заменить ссылку `current` на проверенный релиз и обновить `active.json`.
   Если менялась конфигурация Nginx, сначала выполнить `nginx -t`, затем reload.
5. Проверить HTTPS, отдаваемые файлы, обе проекции, поиск, полёт и reload
   в отдельном профиле браузера; проверить доступность сайта вопросов.
6. После успешной проверки убрать прежние серверные релизы, оставив актуальные
   данные и небольшой журнал публикации. Не удалять локальные данные пользователя.

HTML и изменяемые метаданные отдаются с `no-cache`; папки ревизий — с длительным
кешированием. Для текстовых файлов включён gzip. Сохранение остаётся в
localStorage браузера и привязано к адресу сайта; локальное сохранение
с `127.0.0.1:8765` автоматически на публичный адрес не переносится.
