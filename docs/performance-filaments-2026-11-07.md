# Появление и исчезновение нитей: 07.11.2026

Продолжение оптимизаций зума и проекций. Проверена полная сеть из 15 421 нити
SDSS, 275 599 исходных 3D-вершин. Каталоги, физические координаты, точность
орбит, формулы полёта и формат сохранения не менялись.

## Причины и изменения

1. При каждом шаге зума заново создавались локальные пути всех сегментов,
   хотя в полной и радиальной проекции меняется только положение их якоря.
   Ключ зависел от масштаба и viewport. Теперь точные локальные пути и границы
   переиспользуются; для среза ключ содержит действительные границы Z-слоя.
   Проверка исходных координат замечает замену массивов и изменения на месте.
   В одном кадре проверка выполняется один раз. Кэш ограничен четырьмя срезами
   на объект, исходные массивы не изменяются.
2. Экранные пути, точки и буферы отсечения создавались заново сотнями тысяч
   объектов за кадр. Теперь у загруженной нити один переиспользуемый экранный
   буфер. Целиком видимые сегменты используют уже спроецированные точки;
   отдельные концы отсечения создаются только при необходимости. При панораме
   каждая экранная точка сдвигается ровно один раз. Независимые подпути
   сохранены: стыки, прозрачность, наведение и линии не изменились.
3. Модели геометрии разрешаются один раз за синхронный проход. Контуры нитей
   раньше попадали и в подготовку точечных значков; теперь эти проходы сразу
   пропускают их. Для уже загруженных объектов полного слоя не повторяется
   проверка его готовности. Стиль canvas сохраняется один раз на проход,
   сохраняя порядок и отдельное смешивание каждого контура.
4. Обращение `globalThis.MapDetails` не находило верхнеуровневый `const`.
   Поэтому космологическая группировка строила новый индекс OBJECTS для
   каждой нити. Теперь используется действительный индекс кадра, а вне кадра
   остаётся свежий поиск. Временные кэши очищаются в `finally`.
5. Полная сцена содержала 16 625 космологических привязок при прежнем лимите
   около 16 тысяч. Весь кэш очищался посреди рисования, и следующие кадры опять
   становились холодными. Теперь бюджет — 32 768 записей; при переполнении
   удаляется одна самая старая запись. Это ограничение памяти, не числа
   научных объектов: удалённая привязка вычисляется заново при обращении.

## Попарные замеры Chrome

Отдельный headless-профиль, 1440 × 1000 CSS px, DPR 1, один и тот же загруженный
набор: 6 585 основных объектов, 15 421 объект слоя, 13 403 потоковые записи.
Загрузка на время сравнения заморожена. До/после — функции из снимка начала
этого продолжения и итоговые функции, переключаемые в одной странице.

| Сценарий | До | После |
| --- | ---: | ---: |
| Переход через появление/исчезновение, средний кадр | 152,34 мс | 103,28 мс |
| Тот же переход, p95 | 239,40 мс | 131,20 мс |
| Первый кадр при cosmicTime = 100 000 лет | 3158,85 мс | 291,35 мс |
| Последующие меняющие масштаб кадры при том же времени | 3022,25 мс | 131,15 мс |
| JS heap и backing storage после GC в этой сцене | 399,44 MiB | 248,97 MiB |

Первая пара строк — медиана трёх чередующихся пар, 64 кадра на вариант:
масштаб 1,7 → 3,1 → 1,7 млрд св. лет. Видимое число контуров совпало на каждом
шаге, включая полное исчезновение. Следующие строки — две пары после очистки
космологического кэша; в обеих версиях одинаковый масштаб и физическое состояние.
Для последующих кадров исключён первый шаг без изменения масштаба: он использует
растровый кэш панорамы. Первый кадр включает создание геометрических буферов.

Это измерение JS-кадра в указанной тяжёлой сцене, без периодического сохранения
и UI-прогнозов. Оно не означает 60 FPS на всех устройствах. Полная сеть всё ещё
рисуется через Canvas 2D; оставшийся порядок 100–140 мс требует дальнейшей работы.
Следующий крупный кандидат — отдельный GPU-слой нитей с точной проверкой
прозрачности пересечений и попаданий; сначала нужен отдельный сравнительный
прототип. Нельзя объединять пересекающиеся прозрачные нити в один stroke без
проверки: это меняет смешивание.

## Проверки и ограничения

- `verify-filament-performance.mjs` включён в `verify.mjs`: точные сегменты,
  срезы, изменения исходных координат, границы памяти, повторное использование
  экранных буферов, очистка кадров и отсутствие полного сброса привязок.
- Прошли проверки runtime-performance, map-interaction-performance,
  map-render-cache, map-filters, map-visibility, area-labels, orbit-paths,
  system-view, galaxy-identities, map и `verify-stream.mjs`.
- Браузер: 54 точных сравнения изображения, всех экранных вершин/сегментов,
  подписей и попаданий до/после; обе темы, desktop/mobile, full/slice/radial,
  переход через исчезновение и малый pan. Шесть случаев — с ненулевым cosmicTime.
  Реальные поиск, старт, пауза, wheel/drag, кнопки проекций, точный save/reload
  и прибытие к Сириусу прошли; топливо совпало точно, ошибок JS нет.
  Синтаксис и scoped diff-check прошли, HTTP index и все 58 JS/CSS совпали с
  диском; семь изменённых cache keys соответствуют SHA-256 файлов.
- `verify-extended-geometry.mjs` в рабочей копии передаёт строку режима вторым
  аргументом `indexBounds`, который ожидает модель. Это тот же TypeError на
  снимке до задачи. Без изменения репозиторного теста выполнен временный запуск
  с корректными вызовами `indexBounds(o)`: весь аудит прошёл — 229 630 записей,
  все 15 421 нити и 275 599 вершин, 11 050 компонентов галактик, 384 орбитальных
  отсчёта, ни одной отсутствующей модели.
- Общий `verify.mjs`: 84 PASS за 240 секунд, затем установленный лимит времени.
  Полный успешный прогон не заявляется. Отдельный `verify-map-slice.mjs` не
  завершился за 120 секунд при чтении прежних файлов среза; повторный журнал
  файлового ввода-вывода завершился на
  `dist/map-slices/80c2cb30f81a/6d31fc4ba60ee78a0f4c.json`.
- `verify-cosmology.mjs` сохраняет прежнее ожидание `followShip === false`
  после первого `focusShip()`. Текущая кнопка включает слежение; тот же сбой
  воспроизводится со снимками исходников до продолжения. Тест не менялся.
